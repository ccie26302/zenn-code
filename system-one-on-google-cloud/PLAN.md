# 検証計画 v2: Jev の本質を Google Cloud で実装して測る（事前登録）

v1 はレビューで差し戻し。主な理由: コーパスの言い回しと正解が1対1で、金額を読まない分類器が91.7%を出した。

## 本質の定義（v1から変更）

System One の存在理由は「ソフトウェアが分岐に使える確率を返すこと」。
ただし**校正（ECE）だけでは本質にならない**（常に0.25を返すモデルは ECE ≒ 0 だが役に立たない）。
実務の問いは「**その確率でしきい値を切ったとき、誤りを x% 以下に抑えて何割を自動化できるか**」。

## 主要評価指標

- **E1（主）自動化率@誤り2%**: 最大確率でしきい値を切り、上位から採用。採用分の誤り率が2%以下となる最大の採用率。1%・5%も併記
- **E2（主）対数損失**: 真の確率を出したときに最良となる適正スコア。ε=1e-6 でクリップ
- 副: 正答率（全体／金額が決め手の層）、Brier、予測ラベルの ECE（等幅10ビン・等件数ビンの両方）

## 比較する方式（すべて global エンドポイント）

| 条件 | 方式 | モデル | 位置づけ |
|---|---|---|---|
| A1 | enum 1トークン + logprobs(上位19) | gemini-2.5-flash, 思考オフ | Jev が「LLMラッパー」と呼んだ方式 |
| A2 | 同上 | gemini-2.5-flash-lite | 同・軽量版 |
| B1 | 埋め込み + ロジスティック回帰 | text-multilingual-embedding-002 | **タスク専用の小型判定器**（規程を読まず、ラベルから学ぶ） |
| B2 | 同上 | gemini-embedding-001 | 同・高次元版 |
| C1t | 判定と確信度を言わせる | gemini-3.8-flash, thinking_level=LOW | 最新モデルの現実解 |
| C1d | 4選択肢の分布を言わせる | gemini-3.8-flash, LOW | 同・分布版 |
| C2t | 判定と確信度を言わせる | gemini-2.5-flash, 思考オフ | **A1 と同じモデルで方法だけ違う対照** |
| C2d | 4選択肢の分布を言わせる | gemini-2.5-flash, 思考オフ | 同・分布版 |

A1 と B1 は「単一パス」の点では同じ（A1 も出力1トークンで自己回帰は1回）。違いは**規程を実行時に読むか、ラベルから学ぶか**。

## 予備調査で確定した制約

- logprobs は gemini-2.5 世代のみ。3.8-flash / 3.1-flash-lite は `400 Logprobs is not supported`
- 3.8-flash は `thinking_budget=0` を無視して思考する。`MINIMAL` は拒否、最小は `LOW`
- enum 制約つきの logprobs は4記号に正規化された値。制約なしだと4記号の質量は約0.75
- temperature を変えても logprobs は変わらない（0 と 1.0 で同一）
- temperature=0・seed 固定でも、呼び出しごとに確率が揺れ、判定が反転することがある（1項目13回中1回）
- 埋め込み方式は既定パラメータで CV 正答率58〜64%、標準化と正則化で84〜86%（**学習データのみで確認**）

## コーパス v2

- 正解は規程から機械的に決まる。テスト400（各クラス100）/ 学習200
- **金額が決め手の層** 185件（承認なし×業務×領収書ありで、5万円未満=承認85 / 以上=保留100）
- **言い回しを学習とテストで分けた**（共有ゼロ。分布外テスト）
- 「要確認」の理由を均等化（用途不明34 / 金額不明33 / 領収書なし33）
- 曖昧な言い回し（二重否定、「証憑」、「了承」）を廃止
- **近道の下限**: 金額を読まず（用途区分・領収書・承認）だけで当てる分類器の正答率 **77.5%**。全方式が超えるべき線
- 規程変更（5万→3万）で正解が反転する項目: 45件

## 事前予測（外れの判定基準つき）

- **P1**: 自動化率@2% で A1 > C2t。**外れ**: A1 ≦ C2t
- **P2**: C1t・C2t は90%以上の項目で確信度100を返す。**外れ**: 確信度100の割合 < 90%
- **P3**: 金額が決め手の層の正答率で、B1 は A1 より10pt以上低い。**外れ**: B1 ≧ A1 − 10pt
- **P4**: 規程変更で反転する項目の正答率は B1 ≦ 10%、A1 ≧ 70%。**外れ**: どちらかを満たさない
- **P5**: 日本からの p50 は B1 < A1 < C1t。**外れ**: 順序が崩れる
- **P6**: A1 で同一入力5回のうち、判定が1回以上食い違う項目が40件中1件以上ある。**外れ**: 0件
- **P7**: 規程を約3,000トークンにすると A1 の p50 は100ms以上増え、B1 は ±50ms に収まる。**外れ**: どちらかを満たさない

## 統計

- 信頼区間: 属性の組（用途区分・金額・領収書・承認）単位のクラスタブートストラップ 10,000回
- 対応のある比較: 正答率は McNemar 正確検定、対数損失は項目ペアのブートストラップ
- 主比較は2つ: **A1 vs C2t**（確率の取り方）、**A1 vs B1**（規程を読むか学ぶか）。それ以外は Holm 補正
- 事後校正（副次）: 学習200件で A には温度スケーリング、C-dist にも温度スケーリング。B はもともと学習済み

## エラーの扱い（事前に決める）

- 精度: エラーは誤答、確率は一様（0.25）として数える（除外すると失敗しやすい方式が有利になるため）
- 速度: エラーは除外し、件数を報告
- 精度側は SDK のリトライ有効（一時的な429を誤答にしない）、速度側は無効

## 実行順

acc（並列）→ policy（並列）→ repeat（並列）→ lat（逐次）→ long（逐次）
速度の測定は並列の測定が終わってから行い、混雑を混ぜない。

## やらないこと（理由つき）

- **Jev 本体の測定**: APIキーがない
- **Gemma を自前で立てて選択肢のロジットを直接読む方式**: A1 はすでに1回の prefill と1トークンで、4記号の質量は0.9998以上。上位k件の切り捨てがほぼ効いていないため、確率の質について A1 と本質的な差が出にくい。差が出るのは自前ホスティング（データの所在）の論点で、別記事の題材とする
- **Vertex AI の教師ありチューニング**: 時間と費用の割に、「規程を読むか学ぶか」の論点は B で代表できる
- **サンプリング一致率（温度1でN回）**: 呼び出しがN倍になる。確率の揺れは repeat で別途測る
- **Jev の API へのキーなしリクエスト**: 利用規約上の扱いが不明なため行わない

## 追加測定（事後・探索的）：思考とモデル世代の切り分け

本測定のあと、外部レビューで「3.8 Flash（思考あり）と 2.5 Flash（思考なし）の差は、思考の有無とモデル世代が交絡している」と指摘された。
同じ 2.5 Flash で思考を与えた条件を追加する。事後の追加なので主結果ではなく探索的な結果として扱い、測る前にこの節をコミットする。

条件（すべて gemini-2.5-flash、global、temperature=0、seed=42）

- A1k128: enum + logprobs、thinking_budget=128
- A1k512: enum + logprobs、thinking_budget=512
- C2k512: 確信度を言わせる（top）、thinking_budget=512

対象：テスト400件 + 学習200件（生成系にとって学習分は別の言い回しの未見テスト）。エラーは主分析で誤答・一様確率。
速度：逐次、条件順をシャッフル、先頭5件は捨てる、リトライ無効、通信下限つき、n=50。

予測（外れの基準）

- P8：A1k512 のテスト正答率は 95% 以上。95% 未満なら「思考で解ける」は 2.5 では成り立たず、世代差の寄与が大きいと判定。
- P9：A1k512 の自動化率@誤り2%（テスト）は 50% 以上。50% 未満なら「思考で正確になっても確率は自動化に使えない」と判定。
- P10：A1k512 の速度 p50 は 1,500ms 以上。1,500ms 未満なら「速く・正確で・自動化に使える」の中間構成が存在しうると判定。
